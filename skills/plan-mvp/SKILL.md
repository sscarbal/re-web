# Plan the MVP

## Inputs

- Current project audit and verified business/brand sources.
- Target audiences, operational capacity, launch constraints and unresolved owner choices.

## Procedure

1. State the website's primary business job and critical user journeys.
2. Map existing capabilities and content to those journeys.
3. Define must-have, soon-after, later and remove/archive scopes.
4. Prefer the Concierge MVP: static catalog and unified human inquiry over transactions.
5. Include content, design, technical, SEO, accessibility, performance, security, legal/privacy and deployment work.
6. Break work into independently testable tasks with priority, complexity, dependencies, files, acceptance and approval owner.
7. Define measurable release gates and the first ten executable actions.

## Quality checklist

- Every must-have supports a launch journey or mandatory quality gate.
- Every deferred feature has a reason and revisit trigger.
- Human content/provider/legal decisions are explicit dependencies.
- Scope fits workshop operations and avoids speculative platforms.

## Expected output

An exact page/feature/content scope, acceptance criteria, phased backlog, dependencies, approval gates and immediate actions.

## Avoid

- Treating all documented future specs as MVP.
- Optimizing architecture before confirming content and conversion.
- Using vague tasks such as “improve SEO” without acceptance criteria.
